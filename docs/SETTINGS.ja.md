# 設定

設定は 1 つのファイル（`settings.json`）にまとまっていて、GUI（PC・スマホ）と CLI が同じ物を読みます。どの項目も既定は `auto`（PC を調べてアプリが決める）です。次の起動から効きます。

- 置き場: 環境変数 `SYNC_HOME`、無ければ `%LOCALAPPDATA%\SyncStrata` の `settings.json`。
- コマンドは Windows では `sync`、Linux では `sync.sh` です（以下は `sync` で書きます）。
- 読む: `sync settings get`　書く: `sync settings set <名前> <値|auto>`　起動のときだけ上書き: `sync up --<名前> <値>`

## よく使う項目

| 名前 | 値 | 説明 |
|---|---|---|
| `model` | `auto`・`sync-xs`・`sync-s`・`sync-m` | 使うモデル。`auto` は RAM と VRAM から選びます（README の表） |
| `tail_skip` | `auto`・`4`・`7`・`10` | 1 トークンごとに計算する専門家の数を減らす設定（R4・R7・R10）。数が小さいほど速く、品質は少し下がります。`10` は省きません。`auto` は VRAM 16 GB 以上、または RAM 48 GB 以上かつ VRAM 12 GB 以上なら `7`、ほかは `4` |
| `context` | `auto`・`32768`・`65536`・`131072`・`262144`（`32k` などとも書けます） | 最大コンテキスト長（トークン）。長いほど VRAM を使います。`auto` は VRAM で決めます（下の表） |
| `kv_format` | `auto`・`k8v4`・`k8`・`k4` | 会話の記憶（K/V）の量子化。ふだんは `k8v4`、`k4` は VRAM がいちばん少なく済みます。`auto` は VRAM で決めます |
| `ram_max_gib` | `auto`・数 | モデルの写しに使う RAM の上限（GiB） |
| `vram_reserve_mib` | `auto`・数 | ほかのアプリのために空けておく VRAM（MiB） |
| `models_dir` | `auto`・道のり | モデルの置き場。`auto` は `SYNC_HOME\models` |
| `ram_squeeze` | `auto`・`off` | メモリの追い出し。起動のときと、モデルを切り替えるときに 1 回だけ、ほかのアプリが使っている RAM を追い出して、空いた分をモデルに回します（アプリは閉じません）。`auto`（既定）は入、`off` で切ります。追い出した量は、起動の理由の欄に出ます |
| `expert_learning` | `on`・`off` | 専門家の並びを、この PC での会話から学習して保存します。既定は `off` です。Sync-S・R4 の dsh の会話で測ったところ、学習した並びは本家の並びより速くならなかった（93.7 対 96.1 tok/s）ため、既定では入れていません。`on` にすると、学習した並びを `SYNC_HOME\engine-data` に保存します |

## コンテキスト設定を確かめる

`auto` のときは VRAM で次のように決まります（片方だけ `auto` なら、決めた方に合わせます）。

| VRAM | `context` | `kv_format` |
|---|---|---|
| 12 GB 以上 | 256K | k8v4 |
| 10〜11 GB | 128K | k8v4 |
| 8〜9 GB | 64K | k4 |

VRAM に入らない組は、GUI でも CLI でも選べません（CLI は理由を出して断ります）。会話がこの長さを超えて VRAM が足りなくなると、遅くなってから止まり、エンジンが起こし直されます。

GUI では「起動の設定」→「コンテキスト設定」で選べます。`sync ctx` で、いまの設定・自動の値・実際に使っている値が出ます。起動したエンジンが「この長さを超えると VRAM が足りない」と知らせたときは、「この設定だと約 N トークンまで」と出ます（それより長いと遅くなり、やがて失敗します）。dsh の会話の要約が始まる長さも、この設定に合わせて起動のたびに決まります（文脈が 262,144 のときは 188,416 トークンから。文脈の 9 割と、「文脈 － 返事の上限 65,536 － 余白 8,192」の小さい方です）。会話の画面の「要約が始まる長さ」にも同じ値が出ます。

## Hugging Face のトークン

非公開の置き場からモデルを落とすときだけ要ります（読み取り専用のトークンで足ります）。「コンテキスト設定」の画面の「Hugging Face のトークン」に入れます。トークンはアプリ専用の置き場（`SYNC_HOME\hf`）に保存され、PC 全体の Hugging Face のログインは使いも読みもしません。

## つなぎ方の項目

| 名前 | 既定 | 説明 |
|---|---|---|
| `api_port`・`api_host` | `8080`・`127.0.0.1` | API の待ち受け。`127.0.0.1` 以外にするときは鍵が要ります（[API.ja.md](API.ja.md)） |
| `lan_remote` | `off` | スマホからの接続（`off`・`lan`・`tailscale`）。PC の画面と CLI からだけ変えられ、dsh を起こし直すと効きます（[REMOTE.ja.md](REMOTE.ja.md)） |
| `dsh_port`・`relay_port`・`proxy_port` | `3080`・`3081`・`8081` | dsh と中継の番号。ほかのプログラムが番号を使っていると（`api_port` も同じ）、`sync up` が近くの空いている番号を選んでここに書き、画面に出します。以後はその番号を使います。手で決めることもできます |

## 会話の控え

会話の続きを速く始めるために、エンジンは会話の K/V を控えとしてファイルに残します。1 つで 0.4〜0.5 GiB ほどです。

| 名前 | 既定 | 説明 |
|---|---|---|
| `sessions_dir` | `auto` | 控えの置き場。`auto` は、モデルの置き場が `SYNC_HOME` と別のドライブなら「モデルの置き場の親フォルダー\SyncStrata-sessions」、同じドライブなら `SYNC_HOME\engine-sessions` です |
| `sessions_max_gib` | `auto` | 控えの合計の上限（GiB）。`auto` は 20 と、「そのドライブの空き ＋ 控え」の 1 割の小さい方（最低 2）です。超えると、起動のときと止めたときに、古い物から消します（いちばん新しい 1 つは残します）。空きが 10 GiB 未満のときは、新しい控えを書きません |

## 会話の画面の設定

会話の画面（アプリの枠）は、エンジンと CPU・GPU を取り合わないように、自分の子プロセスの優先度を下げます。この 2 つは枠が `settings.json` を直接読みます。`sync settings set` では変えられないので、`settings.json` に書くか、起動の引数・環境変数で渡します。優先は「引数 → 環境変数 → `settings.json` → 既定」の順で、次に画面を開いたときから効きます。

| 名前 | 値 | 説明 |
|---|---|---|
| `gui_priority` | `cpu-low`（既定）・`low`・`idle`・`normal` | 画面の子プロセスの優先度（引数 `--gui-priority`、環境変数 `SYNC_GUI_PRIORITY`）。`cpu-low` は CPU の優先度だけを下げます。`low` はそれに加えて GPU の優先度も下げます（Windows）。`idle` は CPU と GPU をいちばん低くします（画面のなめらかさは落ちることがあります）。`normal` は何も変えません。Linux は、`cpu-low`・`low` が nice +5、`idle` が nice +15（と I/O の優先度）で、GPU の優先度は触りません。ほかの値は `low` として扱います |
| `gui_gpu` | `auto`（既定）・`on`・`off` | 画面の描画に GPU を使うか（引数 `--gpu`、環境変数 `SYNC_GUI_GPU`）。`off` は CPU で描きます。Linux の `auto` は、窓が白くなるのを避ける設定だけを入れます。WSL の中では `auto` でも CPU で描きます |

## 速くするために

- 動かしている間は、GPU やメモリを多く使うアプリ（ゲーム、動画の書き出し、ブラウザーの重いページ）を閉じてください。`sync doctor` で、いま使っているアプリと勧めが出ます。
- モデルは NVMe の SSD に置いてください。
